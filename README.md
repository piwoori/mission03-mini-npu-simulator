# Mission 03 - Mini NPU Simulator

## 1. 프로젝트 소개

Mini NPU Simulator는 입력 패턴과 필터 간의 **MAC(Multiply-Accumulate)** 연산을 수행하여 입력 패턴이 Cross(+)와 X 중 어느 형태에 가까운지 판정하는 Python 콘솔 프로그램입니다.

본 프로젝트에서는 Python 기본 문법만 사용하여 MAC 연산을 직접 구현하였으며, 사용자 입력 모드와 `data.json` 자동 분석 모드를 제공합니다.

---

## 2. 실행 방법

프로젝트 디렉토리에서 아래 명령어를 실행합니다.

```bash
python3 main.py
```

프로그램 실행 후 원하는 모드를 선택합니다.

```text
=== Mini NPU Simulator ===
[모드 선택]
1. 사용자 입력 (3x3)
2. data.json 분석
```

* **1번** : 3×3 필터와 패턴을 직접 입력
* **2번** : `data.json` 파일을 이용한 자동 분석

> `data.json`은 `main.py`와 같은 디렉토리에 위치해야 합니다.

## 3. 구현 내용

### 3.1 MAC(Multiply-Accumulate) 연산

동일한 위치의 패턴과 필터 값을 곱한 후, 모든 결과를 누적하여 하나의 점수를 계산합니다.

```python
score += pattern[row][column] * filter_data[row][column]
```

MAC 점수는 패턴과 필터의 같은 위치에 있는 값이 얼마나 많이 겹치는지를 나타냅니다.

예를 들어 패턴과 필터의 동일한 위치에 모두 `1`이 존재하면 다음과 같이 점수가 증가합니다.

```text
1 × 1 = 1
```

반대로 한쪽 값이 `0`이면 다음과 같이 점수가 증가하지 않습니다.

```text
1 × 0 = 0
0 × 1 = 0
```

따라서 패턴과 특정 필터의 활성 위치가 많이 일치할수록 누적되는 MAC 점수가 커집니다.

본 프로그램에서는 이를 기준으로 **더 높은 MAC 점수를 가진 필터와 입력 패턴이 더 유사한 형태라고 판단**합니다.

### 3.2 사용자 입력 모드

사용자는 다음 순서대로 입력합니다.

1. 필터 A 입력
2. 필터 B 입력
3. 패턴 입력

프로그램은 다음 정보를 출력합니다.

* A 점수
* B 점수
* 평균 연산 시간(10회)
* 최종 판정(A / B / 판정 불가)

사용자 입력 모드에서는 사람이 직접 결과를 확인하므로 동점일 경우 `"판정 불가"`라는 직관적인 표현을 사용합니다.

### 3.3 data.json 분석 모드

프로그램은 다음 순서로 동작합니다.

1. 필터 로드
2. 패턴 분석
3. MAC 연산
4. PASS / FAIL 판정
5. 성능 분석
6. 결과 요약

패턴 이름(`size_5_1`)에서 크기 정보를 추출하여 해당 크기의 필터를 자동으로 선택합니다.

예시:

```text
size_13_2
      ↓
size = 13
      ↓
filters["size_13"]
```

패턴은 다음 코드에서 불러옵니다.

```python
pattern = pattern_data["input"]
```

필터는 패턴 이름에서 추출한 크기를 이용해 선택합니다.

```python
filter_key = f"size_{size}"

cross_filter = data["filters"][filter_key]["cross"]
x_filter = data["filters"][filter_key]["x"]
```

### 3.4 라벨 정규화

`data.json`에서는 Cross 패턴이 `"+"`, X 패턴이 `"x"`로 표현되어 있습니다.

프로그램 내부에서는 판정 결과를 `"Cross"` 또는 `"X"`로 사용하기 때문에 다음 함수를 이용하여 라벨 표현을 통일합니다.

```python
def normalize_label(label):
    if label == "+":
        return "Cross"
    elif label == "x":
        return "X"
    else:
        return label
```

`normalize_label()`을 별도 함수로 분리한 이유는 라벨 변환 로직을 한 곳에서 관리하기 위해서입니다.

이를 통해 같은 변환 코드를 여러 위치에 반복해서 작성하지 않아도 되며, 향후 새로운 라벨이 추가되거나 표현 방식이 변경될 경우 해당 함수만 수정하면 되므로 **유지보수성과 확장성을 높일 수 있습니다.**

---

### 3.5 동점 판정

부동소수점 연산에서는 매우 작은 계산 오차가 발생할 수 있기 때문에 단순히 `==` 연산자로 두 실수를 비교하지 않고 `epsilon` 값을 사용합니다.

```python
epsilon = 1e-9

if abs(cross_score - x_score) < epsilon:
    return "UNDECIDED"
```

`1e-9`는 다음 값을 의미합니다.

```text
1 × 10⁻⁹ = 0.000000001
```

즉, 두 MAC 점수의 차이가 `0.000000001`보다 작으면 사실상 동일한 값으로 판단합니다.

이 값은 부동소수점 계산에서 발생할 수 있는 매우 작은 오차를 허용하기 위한 기준값이며, 입력 데이터의 값 범위나 요구되는 정밀도에 따라 조정할 수 있습니다.

#### 모드별 동점 처리 방식

사용자 입력 모드와 JSON 분석 모드는 동점 상황에서 사용하는 표현이 다릅니다.

```text
사용자 입력 모드 → "판정 불가"
JSON 분석 모드   → "UNDECIDED"
```

두 경우 모두 **두 점수가 사실상 같아 어느 필터와 더 유사한지 판단할 수 없다는 동일한 의미**를 가집니다.

사용자 입력 모드는 사람이 직접 확인하는 모드이기 때문에 이해하기 쉬운 한글 표현인 `"판정 불가"`를 사용하였고, JSON 분석 모드는 자동 테스트와 결과 비교에 사용되므로 일정한 프로그램용 라벨인 `"UNDECIDED"`를 사용하였습니다.

### 3.6 입력 및 데이터 크기 검증

다음 사항을 검증합니다.

* 숫자가 아닌 사용자 입력
* 한 줄에 숫자가 3개가 아닌 경우
* JSON 데이터의 필터와 패턴 크기 불일치

행렬 크기 검증은 다음 함수를 통해 수행합니다.

```python
def is_valid_size(matrix, size):
    if len(matrix) != size:
        return False

    for row in matrix:
        if len(row) != size:
            return False

    return True
```

JSON 데이터가 잘못 수정되거나 예상과 다른 크기의 패턴 또는 필터가 들어올 경우 MAC 연산 과정에서 잘못된 결과 또는 인덱스 오류가 발생할 수 있습니다.

따라서 MAC 연산 전에 다음과 같이 패턴과 두 필터의 크기를 검사합니다.

```python
if (
    not is_valid_size(pattern, size)
    or not is_valid_size(cross_filter, size)
    or not is_valid_size(x_filter, size)
):
```

크기가 일치하지 않을 경우 프로그램 전체를 종료하지 않고 해당 테스트만 `FAIL` 처리한 후 다음 테스트를 계속 수행합니다.

또한 패턴 이름에서 추출한 크기에 해당하는 `filter_key`가 `data.json`에 존재하지 않을 가능성도 있으므로, 실제 서비스 또는 확장 환경에서는 해당 키의 존재 여부를 확인하거나 `KeyError`를 처리하는 방식을 추가할 수 있습니다.

## 6. 시간 복잡도 및 공간 복잡도 분석

MAC 연산은 모든 행과 열을 한 번씩 순회합니다.

```python
for row in range(len(pattern)):
    for column in range(len(pattern[row])):
```

행과 열을 각각 N번 반복하므로

* 바깥 반복문 : N회
* 안쪽 반복문 : N회

총 연산 횟수는 다음과 같습니다.

```text
N × N = N²
```

따라서 MAC 연산의 시간 복잡도는

```text
O(N²)
```

입니다.

실제 실행 결과에서도 다음과 같이 입력 크기가 증가할수록 연산 횟수가 증가합니다.

| 크기    | 연산 횟수 |
| ----- | ----: |
| 3×3   |     9 |
| 5×5   |    25 |
| 13×13 |   169 |
| 25×25 |   625 |

입력 크기가 증가할수록 연산 횟수(9 → 25 → 169 → 625)가 증가하였으며, 평균 실행 시간 또한 함께 증가하는 것을 확인할 수 있었습니다.

이를 통해 MAC 연산의 시간 복잡도가 `O(N²)`임을 확인할 수 있습니다.

### 공간 복잡도

N×N 형태의 패턴과 필터를 저장하기 위해 각각 N²개의 데이터가 필요합니다.

따라서 입력 데이터 저장에 필요한 공간 또한 크기에 비례하여 증가하며 공간 복잡도는 `O(N²)`로 볼 수 있습니다.

예를 들어 `1000×1000` 행렬은 하나의 행렬에 총 다음 개수의 원소를 가집니다.

```text
1000 × 1000 = 1,000,000개
```

Python에서는 각 숫자와 리스트가 추가적인 메모리 오버헤드를 가지기 때문에 실제 메모리 사용량은 단순히 원소 크기만 계산한 값보다 더 커질 수 있습니다.

## 7. 실패 원인 분석

현재 제공된 `data.json` 기준으로 총 6개의 테스트를 수행하였으며, 3개의 테스트는 FAIL로 판정되었습니다.

실패한 케이스들은 Cross와 X의 MAC 점수가 매우 비슷하게 계산되었습니다.

프로그램은 부동소수점 오차를 고려하기 위해 다음 조건을 사용합니다.

```python
abs(cross_score - x_score) < 1e-9
```

조건을 만족하면 두 점수를 동일한 값으로 판단하고 `UNDECIDED`를 반환하도록 구현하였습니다.

따라서 실제로는 Cross 또는 X와 유사한 패턴이더라도 두 점수 차이가 매우 작으면 어느 쪽과 더 유사한지 확실하게 판단할 수 없으므로 `UNDECIDED`로 처리됩니다.

자동 분석 모드에서는 `expected` 값이 Cross 또는 X로 지정되어 있기 때문에 판정 결과가 `UNDECIDED`인 경우 expected 값과 일치하지 않아 FAIL로 처리됩니다.

즉, 해당 FAIL은 프로그램 실행 오류가 아니라 **현재 적용한 동점 처리 정책과 기대값의 불일치에 의해 발생한 결과**입니다.

## 8. 대형 입력에서의 문제점과 최적화 방안

현재 구현은 Python의 이중 `for`문을 이용하여 모든 원소의 MAC 연산을 순차적으로 수행합니다.

입력 크기가 `N = 1000`일 경우 한 번의 MAC 계산에 필요한 위치별 연산 횟수는 다음과 같습니다.

```text
1000 × 1000 = 1,000,000회
```

입력 크기가 더 증가하면 연산 횟수와 메모리 사용량이 모두 `N²`에 비례하여 증가하기 때문에 실행 시간이 빠르게 증가할 수 있습니다.

대형 입력에서 고려할 수 있는 최적화 방법은 다음과 같습니다.

1. **NumPy 기반 벡터 연산**

   * Python 반복문 대신 내부적으로 최적화된 배열 연산을 사용하여 실행 시간을 줄일 수 있습니다.

2. **블록 단위 처리**

   * 매우 큰 행렬을 한 번에 처리하지 않고 여러 개의 작은 블록으로 나누어 순차적으로 처리하면 메모리 사용량을 조절할 수 있습니다.

3. **병렬 처리**

   * 서로 독립적인 위치의 곱셈 연산을 여러 코어나 가속 장치에서 동시에 처리할 수 있습니다.

4. **데이터 타입 최적화**

   * 필요한 정밀도에 따라 더 작은 자료형을 사용하면 메모리 사용량과 데이터 전송량을 줄일 수 있습니다.

현재 구현은 학습 목적의 기본 MAC 연산 구조를 확인하는 데 초점을 두고 있으며, 대형 입력을 처리해야 하는 환경에서는 위와 같은 최적화가 필요합니다.

## 9. CPU와 NPU의 처리 방식 차이

현재 Python 프로그램은 CPU에서 실행되며 다음과 같은 이중 반복문을 통해 MAC 연산을 수행합니다.

```python
for row in range(len(pattern)):
    for column in range(len(pattern[row])):
        score += pattern[row][column] * filter_data[row][column]
```

CPU에서는 이러한 반복 연산이 프로그램 명령 흐름에 따라 순차적으로 처리되는 비중이 높기 때문에 N이 커질수록 전체 실행 시간이 증가합니다.

반면 NPU(Neural Processing Unit)는 딥러닝 및 행렬 연산에서 자주 사용되는 대량의 MAC 연산을 효율적으로 처리하도록 설계된 가속 장치입니다.

NPU는 다수의 MAC 연산기를 이용하여 여러 위치의 곱셈과 누적 연산을 병렬로 수행할 수 있기 때문에 대규모 행렬 연산에서 CPU보다 높은 처리량을 얻을 수 있습니다.

다만 NPU에서도 무조건 연산 속도만이 병목이 되는 것은 아닙니다.

대규모 데이터를 처리하는 경우 다음 요소가 성능에 영향을 줄 수 있습니다.

* 메모리에서 연산 장치로 데이터를 전달하는 속도
* 메모리 대역폭
* 병렬 처리 가능한 연산의 양
* 데이터 재사용률
* 장치 간 데이터 이동 비용

즉, CPU에서는 순차 반복 연산 자체가 주요 병목이 될 수 있는 반면, NPU에서는 많은 MAC 연산을 병렬화할 수 있지만 **데이터 공급과 메모리 전송이 새로운 병목이 될 수 있습니다.**

Mini NPU Simulator는 이러한 NPU의 실제 하드웨어 병렬 처리를 직접 구현한 것은 아니지만, MAC 연산의 기본 구조와 입력 크기에 따른 연산량 증가를 소프트웨어적으로 확인하기 위한 프로그램입니다.

## 10. 확장 방법

새로운 패턴 또는 라벨을 추가하려면 다음 순서로 확장할 수 있습니다.

### 새로운 패턴 추가

`data.json`의 `"patterns"`에 새로운 테스트 데이터를 추가합니다.

```json
"size_5_3": {
    "input": [
        ...
    ],
    "expected": "x"
}
```

패턴 이름에는 `size_N` 형태로 크기 정보를 포함해야 현재 코드에서 적절한 필터를 자동으로 선택할 수 있습니다.

### 새로운 라벨 추가

새로운 라벨 표현이 추가될 경우 `normalize_label()`에 변환 규칙을 추가합니다.

```python
def normalize_label(label):
    if label == "+":
        return "Cross"
    elif label == "x":
        return "X"
    elif label == "새로운 값":
        return "새로운 라벨"
    else:
        return label
```

필요한 경우 `classify()`의 판정 규칙과 `data.json`의 expected 값도 함께 수정합니다.

이처럼 라벨 변환 기능을 별도 함수로 분리했기 때문에 새로운 라벨 추가 시 관련 코드를 한 곳에서 관리할 수 있습니다.
